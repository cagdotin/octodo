● in development · local-first · plain files

octodo is a task manager made of plain markdown files.

Every task is a file, every status a folder, and all of it is yours.

You plan; your agents pick up the rest over MCP.

Reach it from your phone over Tailscale. Nothing leaves your machine.

how it works/github/roadmap

● the files, cli and mcp server work today. the app is in preview.

01files

A task is a file. A status is a folder.

Moving a task moves its file. Anything that reads markdown can read your tasks, and nothing is lost if octodo disappears. Edit them in vim, sync them with git or iCloud.

~/house-moveocto

02agents

One brain, many arms.

04private

Anywhere you are. Still only yours.

No account and no cloud. Run octo serve on your machine and pair your phone over Tailscale; the server only answers to the token it gave you.

pair a device100.64.0.7:4520
scan to open octodo on your phone
octo servedefaults
bind127.0.0.1, unless you say otherwise
autha token on every request, or a paired session
hostsan allowlist, so DNS rebinding goes nowhere
origincross-site writes are refused
cloudnone. no account, no telemetry

05where it's going

Small at the core, and it extends itself.

Plugins are TypeScript files in your workspace. Ask an agent for a reading-list view and it writes one; keep it, or delete the file. Read the vision.

  • [x]tasks as markdown, statuses and lists as folders
  • [x]cli, http api and mcp server
  • [~]desktop and web app
  • [ ]calendar and a second sidebar for time
  • [ ]habits and recurring tasks
  • [ ]plugins your agents can write

06early access

Not released yet. Usable already.

If you're fine with rough edges, run it from the repository.

$ mise run setup              # node 26 + pnpm
$ bin/octo init ~/house-move
$ octo create "Book the movers" -p high
$ claude mcp add octodo -- octo mcp
$ octo serve                  # app, api and mcp on 127.0.0.1:4520
